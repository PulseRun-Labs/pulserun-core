## Project description

PulseRun is a pay-per-run compute and CI runner protocol built on Stellar and
Soroban. Compute work is metered and bursty but usually paid for retroactively,
which is why 27% of cloud spend is wasted on idle or over-provisioned resources
(Flexera, *State of the Cloud 2025*) and 83% of container cost is tied up in idle
resources (Datadog). PulseRun inverts the payment model: a requester locks a
budget in a Soroban escrow before a job starts, a runner executes the job and
submits a metered execution proof, and the contract settles for the seconds
actually executed while returning the unspent remainder. The escrow enforces the
terms on both sides — the runner is funded before running, the requester can
never be billed past their ceiling, and either party can freeze a suspicious
proof inside a dispute window. This repository is the contracts layer; the
application layer lives in `pulserun-client`.

## Repository relationship

The project is split into two repositories so each concern can be reviewed and
supported independently:

- **`pulserun-core`** (this repo) — the Soroban contracts. `PulseEscrow` holds
  and settles funds; `mock_token` exists only to exercise settlement in tests.
  It is a pure Rust workspace with no application code.
- **`pulserun-client`** — the application layer: a TypeScript SDK wrapping the
  contract calls, a web app for requesters and runners, and an indexer that
  follows job state (currently by polling views; contract events are planned).

How they connect technically: the client builds and signs Soroban transactions
against the deployed `PulseEscrow` id, using the escrow's published error codes
and `ComputeJob`/`ExecutionProof` types restated in the SDK. Contract addresses
are passed to the client at build time through environment variables
(`PULSEESCROW_ID`, `MOCKTOKEN_ID`) — see
[`docs/deployments/testnet.md`](docs/deployments/testnet.md) for the source of
truth. An indexer subscribes to contract events once the event-emission issue
below lands; until then it reconciles state from `get_job`.

## Issue sizing

The backlog is generated by [`scripts/create-issues.sh`](scripts/create-issues.sh),
which creates every issue below in one idempotent run. Issues carry a size label
(`trivial`, `medium`, or `high`) so contributors can pick work that matches the
time they have.

## Planned issues

### Contract — lifecycle and settlement

- **feat(escrow): add admin dispute resolution to split or refund escrowed funds** (high) — `dispute_job` currently freezes funds with no way to release them.
- **feat(escrow): emit contract events on lifecycle transitions** (medium) — lets the indexer stop polling views.
- **feat(escrow): add runner accept/decline so runners are not silently assigned** (medium) — stops collateral being locked against an unwilling runner.
- **feat(escrow): add per-job metadata hash for off-chain job specs** (medium) — pins the job's *input*, not just its output.
- **feat(escrow): allow anyone to trigger timeout refund after a grace period** (medium) — recovers funds if the requester goes quiet.
- **feat(escrow): add paginated listing of jobs by requester and runner** (medium) — makes party history queryable on-chain.
- **feat(escrow): add update_dispute_window admin entrypoint and get_config view** (trivial) — tunable config and one-call reads.

### Contract — economics and safety

- **feat(escrow): emit a protocol fee to the admin on settlement** (high) — makes the protocol capturable with integer basis-point math.
- **feat(escrow): add emergency pause for create_job and claim_payout** (high) — halts a live flaw without touching locked funds.
- **feat(escrow): validate payment_token is a contract before locking collateral** (medium) — clear error instead of a confusing cross-contract revert.

### Testing

- **test(escrow): add invariant test that contract balance equals sum of open escrows** (high) — the core safety property as a property test.
- **test(escrow): add table-driven cases for settlement cap and duration bounds** (medium) — boundary and overflow coverage.
- **test(mock_token): cover burn insufficiencies and self-transfer edges** (trivial) — a token bug must not mask an escrow bug.

### Docs and CI

- **docs: write a threat model and storage/TTL migration note** (medium) — program-ready security documentation.
- **ci: add cargo-deny dependency and license audit job** (trivial) — supply-chain gate.
- **ci(wasm): assert wasm size budget and publish artifacts per release** (trivial) — guards binary growth.
