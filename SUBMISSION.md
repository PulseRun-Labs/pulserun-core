## Project description

PulseRun is a pay-per-run compute and CI runner protocol on Stellar. Compute
work is metered and bursty but usually paid for retroactively, which is why 27%
of cloud spend is wasted on idle or over-provisioned resources (Flexera, *State
of the Cloud 2025*) and 83% of container cost is tied up in idle resources
(Datadog). PulseRun inverts the payment model: a requester locks a budget in a
Soroban escrow before a job starts, a runner executes the job and submits a
metered execution proof, and the contract settles for the seconds actually
executed while returning the unspent remainder. The escrow enforces the terms on
both sides — the runner is funded before running, the requester can never be
billed past their ceiling, and either party can freeze a suspicious proof inside
a dispute window. This repository is the contracts layer; the application layer
lives in `pulserun-client`.

## Repository relationship

The project is split into two repositories so each concern can be reviewed and
supported independently:

- **`pulserun-core`** (this repo) — the Soroban contracts. `PulseEscrow` holds
  and settles funds; `mock_token` exists only to exercise settlement in tests.
  It is a pure Rust workspace with no application code.
- **`pulserun-client`** — the application layer: a TypeScript SDK wrapping the
  contract calls, a web app for requesters and runners, and an indexer that
  follows job state (currently by polling views; contract events are planned).

How they connect technically: the client builds and signs Soroban transactions
against the deployed `PulseEscrow` id, using the escrow's published error codes
and `ComputeJob`/`ExecutionProof` types restated in the SDK. Contract addresses
are passed to the client at build time through environment variables
(`PULSEESCROW_ID`, `MOCKTOKEN_ID`) — see [`docs/deployments/testnet.md`](docs/deployments/testnet.md)
for the source of truth. An indexer subscribes to contract events once the
event-emission issue below lands; until then it reconciles state from `get_job`.

## Planned issues

### Contract — lifecycle and settlement

- **feat(escrow): add admin dispute resolution to split or refund escrowed funds** (high, 200) — `dispute_job` currently freezes funds with no way to release them.
- **feat(escrow): emit contract events on lifecycle transitions** (medium, 150) — lets the indexer stop polling views.
- **feat(escrow): add runner accept/decline so runners are not silently assigned** (medium, 150) — stops collateral being locked against an unwilling runner.
- **feat(escrow): add per-job metadata hash for off-chain job specs** (medium, 150) — pins the job's *input*, not just its output.
- **feat(escrow): allow anyone to trigger timeout refund after a grace period** (medium, 150) — recovers funds if the requester goes quiet.
- **feat(escrow): add paginated listing of jobs by requester and runner** (medium, 150) — makes party history queryable on-chain.
- **feat(escrow): add update_dispute_window admin entrypoint and get_config view** (trivial, 100) — tunable config and one-call reads.

### Contract — economics and safety

- **feat(escrow): emit a protocol fee to the admin on settlement** (high, 200) — makes the protocol capturable with integer basis-point math.
- **feat(escrow): add emergency pause for create_job and claim_payout** (high, 200) — halts a live flaw without touching locked funds.
- **feat(escrow): validate payment_token is a contract before locking collateral** (medium, 150) — clear error instead of a confusing cross-contract revert.

### Testing

- **test(escrow): add invariant test that contract balance equals sum of open escrows** (high, 200) — the core safety property as a property test.
- **test(escrow): add table-driven cases for settlement cap and duration bounds** (medium, 150) — boundary and overflow coverage.
- **test(mock_token): cover burn insufficiencies and self-transfer edges** (trivial, 100) — a token bug must not mask an escrow bug.

### Docs and CI

- **ci: add cargo-deny dependency and license audit job** (trivial, 100) — supply-chain gate.
